# API service contract (Stage 2)

The Stage 2 thin FastAPI service layer exposes the Stage 1 productization contract over HTTP. It is an **interface layer** — it does NOT re-implement forecasting, monitoring, drift detection, agent reasoning, governance, the model registry, retraining, champion/challenger, rollback, or audit logging. Every endpoint delegates to the existing research implementation.

The service is **read-only** and **advisory-only**. There are no mutation endpoints. Lifecycle action types are blocked by the existing agent firewall (`src/smartgrid_mlops/agents/firewall.py`); the API does not weaken that guarantee.

---

## 1. Architecture

```
Frontend (future, Stage 3)
        ↓
FastAPI (Stage 2: product/backend_api/app/main.py)
        ↓
Productization Contract (src/smartgrid_mlops/productization/forecasting_to_mlops.py)
        ↓
Existing research implementation
   - mlops.registry.ResearchRegistry
   - monitoring.events.make_event
   - governance.policy_engine.GovernanceEngine
   - governance.policies.GovernancePolicy
   - agents.orchestrator.Orchestrator + agents.firewall.firewall_validate
   - champion_challenger.registry.ChampionRegistry
   - mlops.audit.append_audit_event + read_audit_events
   - research artefacts (artifacts/research_tables/, artifacts/model_registry/, etc.)
```

The API is a pure adapter. It does not invent new business logic. It does not re-implement any existing service. It reads existing research artefacts and emits existing Pydantic models for them.

## 5. Governance boundary

The API does NOT expose:

- `POST /models/{id}/promote`
- `POST /models/{id}/deploy`
- `POST /models/{id}/rollback`
- `POST /models/{id}/retrain`
- Any other mutation endpoint

The OpenAPI schema is verified by the test `TestSafetyBoundary::test_api_does_not_allow_lifecycle_via_any_path` to contain no path with `promote`, `deploy`, `rollback`, `retrain`, `change_policy`, `modify`, or `approve_deployment` suffixes.

The Stage 1 firewall guarantee (7/7 lifecycle action types blocked) is preserved by the `TestSafetyBoundary::test_firewall_blocks_all_seven_lifecycle_action_types` test, which re-imports the same firewall module the API uses.

The Stage 1 `run_safety_integration` entry point is re-run by `TestSafetyBoundary::test_stage1_safety_integration_still_passes` and must still report `ALL_SAFETY_TESTS_PASSED`. If a refactor weakens it, the Stage 2 test suite fails.

## 7. Offline limitations (honest)

The OpenAPI `description` and the `HealthStatus.notes` field both state: the system is an **offline evaluation system**. There is no live monitoring, no streaming, no real-time telemetry, and no production deployment. The productization layer's monitoring events are derived from a one-shot read of the frozen final-test evidence; the agent layer is local-rule-based (no LLM is invoked at runtime); the audit ledger is the existing Phase 13 JSONL file.

## 8. Error handling

The API has typed Pydantic v2 request and response models. HTTP errors are returned as a typed JSON envelope:

```json
{ "error": { "type": "http", "status": 404, "detail": "Unknown target 'totally-fake-target'", "path": "/api/forecasts/totally-fake-target" } }
```

Governance denials are returned as the normal `GovernanceDecisionRecord` (HTTP 200 with `decision=DENY`); they are **not** coerced into HTTP 500. This preserves the safety property: a blocked recommendation is visibly identifiable as a governance denial, not an internal error.

| Failure mode | HTTP status | Body |
| --- | --- | --- |
| Unknown target | 404 | `{ "error": { "type": "http", "status": 404, "detail": "Unknown target 'X'; valid: ['load','pv','wind']", "path": ... } }` |
| Invalid request | 400 | same shape |
| Required artefact missing | 503 | same shape |
| Governance denial | 200 | `GovernanceDecisionRecord(decision="DENY", reason_codes=..., ...)` |
| Agent safety block | 200 | `AgentExplanationResponse(firewall_decision="blocked", firewall_reason_code=...)` |
| Internal error | 500 | `{ "error": { "type": "internal", "status": 500, ... } }` |

## 10. OpenAPI documentation

`/docs` (Swagger UI) and `/redoc` (ReDoc UI) are auto-generated by FastAPI. They reflect the actual route definitions, request schemas, and response schemas. The OpenAPI description explicitly states the system is offline evaluation; no simulated real-time infrastructure is described.

## 11. Out of scope

The Stage 2 service does NOT add:

- A frontend (the spec defers this to Stage 3)
- Authentication (no existing architecture requires it; the API is intended for internal use)
- Caching (Redis, in-memory caches, etc.)
- Message queues (Kafka, Celery, Redis Pub/Sub)
- Distributed deployment (Kubernetes, cloud)
- Live model serving (the repository has no serving layer)
- LLM-backed agents (the bounded agents are local-rule-based; the LLM backend interface is documented as a contract only)
- Quantum / QML / GNN / fake real-time telemetry
- Mutation endpoints (governed lifecycle transitions remain the responsibility of the existing research pipeline)

## 12. How to run the API

```bash
# install
pip install fastapi uvicorn httpx

# run (development)
uvicorn product.backend_api.app.main:app --reload

# run (production)
uvicorn product.backend_api.app.main:app --host 0.0.0.0 --port 8000 --workers 1
```

`/docs` and `/openapi.json` describe the 17 endpoints and their schemas.

## 13. How to run the API tests

```bash
.venv/Scripts/python.exe -m pytest tests/test_api_service.py -v
```

The test suite requires `httpx` (installed by `pip install httpx`). It uses FastAPI's `TestClient` and verifies the 17 endpoints + the safety boundary + the no-mutation invariant.
